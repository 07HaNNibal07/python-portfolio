# Проверка проектов и скриншоты

Дата: 9 ноября 2026 года.

Все три проекта запущены локально из отдельных копий в рабочей папке. Для проверки созданы новые PostgreSQL-базы и отдельный Redis. Существующие базы пользователя не подключались и не очищались. Исходные папки на Desktop не редактировались; контрольные суммы скопированных исходных файлов проверены после работы.

## Результаты

| CinemaProject | Миграции обоих сервисов; регистрация и вход; взаимодействие сервисов; каталог и сеансы; бронь, покупка, права владельца и истечение TTL; Celery worker | 4 интеграционных сценария прошли после согласования тестовой фикстуры с текущей схемой фильма. Без изменения фикстуры все 4 теста останавливались на создании фильма с HTTP 422 |

Это проверка перечисленных сценариев, а не утверждение о полном покрытии или готовности к production. Нагрузочное тестирование, внешние OAuth-провайдеры, реальные платежи и LLM не проверялись. Оплата BosnaFitClub демонстрационная; LLM в дипломе пока отсутствует.

## Обнаруженные проблемы

### BosnaFitClub: ошибка регистрации

В `fitness_club/accounts/views.py`, в функции `register`, после сохранения нового пользователя вызывается `login(request, user)` без указания backend. В настройках одновременно подключено несколько authentication backend. Django возвращает HTTP 500 с сообщением о необходимости указать backend.

Пользователь уже успевает сохраниться в БД, но автоматический вход и переход в профиль не завершаются. Обычный вход по email и паролю работает — через него продолжены остальные проверки.

**Исходники не исправлялись.** Для корректного отчёта эта проверка оставлена неуспешной. Профиль на скриншоте получен через реально работающий обычный вход, а не через обход авторизации.

### CinemaProject: тестовая фикстура отстаёт от схемы

`cinema-service/app/schemas/movies.py` требует поля `id` и `picture`, а фикстура `create_session` в `tests/conftest.py` их не передаёт при создании фильма. Первоначальный запуск даёт 4 ошибки на HTTP 422 до проверки бронирования.

Только в рабочей копии фикстуры добавлены обязательные поля. После этого прошли:

1. Бронирование свободного места.
2. Запрет покупки чужой брони.
3. Покупка владельцем брони.
4. Возвращение места в доступное состояние после истечения TTL.

Код приложения не исправлялся. Внешние адреса сервисов заменены на локальные только в рабочей копии.

### IT Career Navigator: настройка запуска тестов

В копии `tests/conftest.py` изменён адрес БД на отдельную тестовую базу и убрано вложенное `pytest_plugins = ["anyio"]`, которое pytest 9 не разрешает в таком расположении. AnyIO уже подключён установленным плагином. После этой настройки все 27 тестов прошли. В выводе есть предупреждения PyJWT о длине тестового секретного ключа; конфигурация исходного проекта не менялась.

## Подготовка окружения

- Использованы существующие Python-окружения проектов. Отсутствовавшие зависимости CinemaProject установлены в отдельную рабочую папку, а не в исходный проект.
- Для CinemaProject сгенерированы временные RSA-ключи. Приватные ключи, `.env` и базы данных не включены в портфолио.
- Применены миграции всех приложений к новым пустым базам.
- Для BosnaFitClub использованы штатные команды `seed_memberships` и `seed_club`, существующие изображения из `media/` и отдельные demo-аккаунты.
- Для CinemaProject демонстрационные фильмы, сеанс, бронь и покупка созданы через работающий API. Изображения постеров взяты из исходного проекта.
- Для диплома две демонстрационные вакансии импортированы через API. Требования были переданы в данных; это не результат LLM-извлечения.
